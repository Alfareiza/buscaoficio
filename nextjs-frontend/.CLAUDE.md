# Frontend (nextjs-frontend)

## Stack
- Next.js 16 (App Router), React 19, TypeScript
- Runs on **Webpack** (`next dev --webpack` / `next build --webpack`), not Turbopack — Webpack does not auto-instrument Server Actions, which matters for Sentry (see below)
- Tailwind CSS + shadcn/ui (Radix primitives) + Heroicons / Lucide / react-icons
- Forms: react-hook-form + Zod (`@hookform/resolvers`)
- FE↔BE contract: `@hey-api/openapi-ts` generates a typed client into `app/openapi-client` from the backend's OpenAPI schema, using the axios adapter (success → `{...response, data}`, failure → raw `AxiosError` with `.error` attached)
- Package manager: **pnpm** (not npm/yarn)
- Tests: Jest + Testing Library
- Errors/tracing/logs: `@sentry/nextjs`

## Auth architecture (read before touching login/register/session code)
Full write-up: `docs/auth.md`. Deeper narrative/history: `memory-bank/systemPatterns.md` § "Frontend auth pattern" / "Passwordless OTP auth pattern".

The frontend is **Server Actions + Edge middleware based** — every backend call is server-to-server from the Next.js server, not the browser (`API_BASE_URL` deliberately has no `NEXT_PUBLIC_` prefix). This is the current implementation, not a locked-in decision — see `memory-bank/activeContext.md` for the open discussion on whether to move to a full SPA or hybrid model.

- **Cookie forwarding**: a server-to-server fetch's `Set-Cookie` lands on the Next.js server, not the browser — `lib/auth-cookies.ts` re-applies it explicitly via a structural `CookieWriter` interface (`set`/`delete`) compatible with both `next/headers`'s `cookies()` (Server Actions) and `NextResponse.cookies` (middleware).
- **Silent refresh via `proxy.ts`**: no client-side refresh timer. On every `/dashboard/:path*` request, `proxy.ts` decodes the access token's `exp`; if expired or within a 2-minute buffer, it refreshes server-to-server against FastAPI (manually forwarding `refreshToken`/`fingerprintToken` as a `Cookie` header, since server-to-server calls don't auto-attach browser cookies). On failure, document GETs clear cookies and 307 to `/login`. **Never 307 a request that has a `next-action` header** — Next posts Server Actions to the current page; a middleware 307 is followed as another Flight POST and is not a navigation (Logout no-op in prod, 2026-08-29). Pass through and let the action `redirect()`.
- **Reactive fallback**: `items-action.ts` checks each result with `isUnauthorizedError()` to catch a token revoked between the middleware's check and the actual call.
- **Cross-tab logout** needs no sync code — cookies are already shared across tabs by the browser; a stale tab self-corrects on its next nav/action via `proxy.ts` or the reactive fallback. No `BroadcastChannel`/`storage`-event code was added on purpose.
- **Page protection is `proxy.ts`'s `matcher` array, and nothing else** — there is no per-page or per-layout auth check; `app/dashboard/layout.tsx` is UI chrome only. A route outside `matcher` is fully public, silently. **To protect a new page**: put it under `/dashboard/...` (automatic) or add its path to the matcher.
- ⚠️ **`proxy.ts`'s `config.matcher` must be a literal array**, not a variable — Next.js can't statically parse a const reference (e.g. `matcher: loginRequiredPaths`), so the proxy silently applies globally instead of the intended routes, causing redirect loops on unprotected paths. Always inline: `matcher: ["/dashboard/:path*"]`.

## Sentry (three isolated bundles — do not merge them)
Next.js compiles three separate JS bundles; each needs its own `Sentry.init()`. A shared `sentry.shared.ts` can pull Node APIs into the Edge bundle and break `proxy.ts` — do not add one.

| File | Runtime | Notes |
|---|---|---|
| `instrumentation-client.ts` | Browser | Loaded automatically; uses `NEXT_PUBLIC_SENTRY_DSN`; exports `onRouterTransitionStart` |
| `sentry.server.config.ts` | Node.js | Server Components, Server Actions, Route Handlers |
| `sentry.edge.config.ts` | Edge | `proxy.ts` runs on Edge |
| `instrumentation.ts` | Next hook | Dynamically imports server vs. edge config so bundles stay isolated; exports `onRequestError` |
| `app/global-error.tsx` | App Router | Catches React render errors |
| `withSentryConfig` in `next.config.mjs` | Build | Source maps + Webpack auto-instrumentation |

Call `Sentry.logger` / `Sentry.captureException` directly in application code — no wrapper in `lib/utils.ts`. Not added on purpose: Session Replay, User Feedback, profiling, `tunnelRoute`, a custom frontend logger, a Jest Sentry mock.

## OpenAPI client sync (dev only)
`nextjs-frontend/watcher.js` (chokidar) watches the shared `openapi.json` and runs `pnpm generate-client` on change. This only runs under `./start.sh` / `make start-frontend` (or the Docker equivalent) — not on Vercel, in CI, or in production builds. A bare `pnpm run dev` starts Next without it, so the generated client can silently drift from the backend.

## Testing gotchas
- Jest's default `jsdom` environment lacks the `Request`/`Response` Web APIs `next/server`'s `NextRequest` needs — any test importing `NextRequest` (e.g. `proxy.test.ts`) needs `/** @jest-environment node */` at the top.
- Next's `redirect()` throws internally in production, but a Jest mock of it does not — code relying on `redirect()` halting execution needs an explicit `return redirect(...)`, otherwise execution falls through under test.
- **`jest.mock("...")` string arguments must use relative paths, not the `@/` alias.** SWC rewrites `@/`-aliased specifiers in real `import` statements at parse time, but not inside `jest.mock()`, so `jest.mock("@/components/x", ...)` fails to resolve while `jest.mock("../components/x", ...)` works. Direct (non-mocked) imports of the module under test can still use `@/`.

## Commands
- `make start-frontend` (or `make docker-start-frontend`) — runs `./start.sh`, which starts Next **and** `watcher.js`. Prefer this over a bare `pnpm dev`.
- `pnpm test` / `pnpm coverage`
- `pnpm lint` / `pnpm lint:fix` / `pnpm prettier` / `pnpm tsc`
- `pnpm generate-client` — manual OpenAPI client regen (normally automatic via the watcher)

## Local ports (customized for this machine, not the template defaults)
Frontend `3000`; backend API `8001` (not `8000`) — see `fastapi_backend/.CLAUDE.md` for backend-side ports.
